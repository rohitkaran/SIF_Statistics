# SIF Risk / Return Terminal

A local, self-contained dashboard for the risk/return profile of India's
**Specialized Investment Funds (SIFs)** — the long-short / allocator / sector-rotation
strategies AMFI publishes separately from mutual funds. Every number traces back to a
NAV file downloaded live from AMFI; nothing is synthetic.

```
sif-dashboard/
├── fetch_amfi_sif.py        # downloads real NAVs, writes nav_data.json, serves the page
├── fetch_sif_portfolios.py  # downloads fund-house PORTFOLIO disclosures (bi-monthly), normalises them
├── sif_dashboard.html       # the terminal (single file, no build step)
├── nav_data.json            # generated by the NAV fetcher — the data the page loads
├── requirements.txt         # deps for the portfolio pipeline only (openpyxl, pdfplumber)
├── portfolios/              # disclosed holdings, committed to the repo
│   ├── registry.json        #   per-AMC disclosure sources (hand-maintained)
│   ├── index.json           #   generated: scheme code → periods available
│   ├── raw/<amc>/<period>/  #   the original Excel/PDF, saved verbatim
│   └── data/<period>/*.json #   normalised holdings the page loads
└── README.md
```

## Quick start

```bash
cd sif-dashboard
python fetch_amfi_sif.py --from 2025-10-01 --to 2026-08-01   # downloads nav_data.json
python fetch_amfi_sif.py --serve                             # http://127.0.0.1:8765
```

Then open **http://127.0.0.1:8765/sif_dashboard.html**.

> Open it through the server, **not** as a `file://` page. AMFI sends no CORS headers and
> a `file://` page can't fetch cross-origin, which is exactly why `--serve` exists (it adds
> `Access-Control-Allow-Origin: *` and proxies live refreshes via `/refresh`).

Python 3 standard library only — no pip installs, no API key.

## Hosting it for free (public + auto-refreshing)

AMFI sends no CORS headers, so a browser on a static host can't pull NAVs directly — the
download has to run server-side. The free, no-server way to keep a public site current is
**GitHub Pages + GitHub Actions**: a scheduled Action runs the fetcher and publishes the folder,
so everyone sees fresh data with zero infrastructure. A workflow is included at
[`.github/workflows/refresh-and-deploy.yml`](.github/workflows/refresh-and-deploy.yml).

**One-time setup** (treat this `sif-dashboard/` folder as the repo root):

```bash
cd sif-dashboard
git init -b main
git add -A && git commit -m "SIF dashboard"
git remote add origin https://github.com/rohitkaran/SIF_Statistics.git
git push -u origin main --force
```

Then on GitHub: **Settings → Pages → Build and deployment → Source = GitHub Actions**. That's it.
The Action runs on push, every weekday at 20:00 IST (after NAVs publish), and on demand from the
**Actions** tab. Your public URL is **`https://rohitkaran.github.io/SIF_Statistics/`**.

- The workflow re-downloads real NAVs each run and deploys them; if AMFI ever blocks the CI
  runner, it falls back to the last committed `nav_data.json` so the site never breaks.
- The in-page **Fetch AMFI ↻** button is for *local* use (it needs `--serve`). On the hosted
  site, freshness comes from the daily Action instead — no button press required.

**Want the live Fetch button to work for visitors too?** Deploy a tiny CORS proxy (e.g. a free
**Cloudflare Worker** that forwards `/refresh` to a run of this fetcher, or proxies the AMFI API
with `Access-Control-Allow-Origin: *`), then open the page as
`https://…/sif-dashboard/?api=https://your-worker.workers.dev`. The dashboard reads the `api`
query param and routes Fetch through it. This is optional — the daily Action already keeps
everyone current.

**Other free static hosts** (Cloudflare Pages, Netlify, Vercel) work the same way for serving the
files; you'd move the scheduled refresh into their equivalent cron/CI, or just keep using GitHub
Actions to commit `nav_data.json`.

## Which endpoint worked

The mutual-fund endpoints (`spages/NAVAll.txt`, `DownloadNAVHistoryReport_Po.aspx`) do **not**
carry SIFs. The obvious analogues — `spages/NAVSIF.txt`, `DownloadSIFNAVHistoryReport_Po.aspx` —
all return **404**. The SIF pages are Next.js apps that fetch JSON client-side, so the real
endpoints were found by grepping the page's `/_next/static/chunks/*.js` bundles for API paths:

| Purpose | Endpoint (all `HTTP 200`, JSON) |
|---|---|
| **Enumerate** every live SIF variant | `https://www.amfiindia.com/api/sif-latest-nav` |
| **History** — full daily series for one scheme | `https://www.amfiindia.com/api/sif-nav-history?query_type=historical_period&sd_id={sd}&from_date={frm}&to_date={to}` |

Details verified during discovery:

- `api/sif-latest-nav` → `36,617 bytes`, **111 scheme variants** across 5 categories / 17 AMCs.
  Each scheme carries a unique `Sd_Id` (e.g. `SIF-120`), `NavName`, `category`, latest NAV + date.
- `api/sif-nav-history` `historical_period` → one `sd_id` returns exactly **one** plan variant's
  `nav_groups[].historical_records[] {date, nav}` (1 : 1, so no cross-scheme duplication).
  Dates accept either `dd-Mmm-yyyy` or `yyyy-MM-dd`; the fetcher sends `dd-Mmm-yyyy`.
- Requests need a **browser `User-Agent`** and `Accept-Encoding: gzip`, or AMFI rejects them.

A real first-5-lines sample of the enumerate response:

```json
{"data":[{"type":"Open Ended Scheme","categories":[{"category":"Equity Oriented Investment
Strategies - Equity Ex-Top 100 Long-Short Fund","groups":[{"SIFName":"Altiva SIF","schemes":[
{"sifId":"47","Sd_Id":"SIF-120","ISINPO":"INF754K30094",
"NavName":"Altiva Equity Ex- Top 100 Long - Short Fund - Direct Plan - Growth",
"Date":"31-Jul-2026","NetAssetValue":10.8161}, ...
```

The **universe** is the 5 SIF strategy categories, which map 1 : 1 to the dashboard's groups:

| Dashboard group | AMFI category | Variants |
|---|---|---:|
| Hybrid Long-Short | Hybrid Investment Strategies – Hybrid Long-Short Fund | 42 |
| Equity Long-Short | Equity Oriented – Equity Long-Short Fund | 38 |
| Ex-Top 100 SMID | Equity Oriented – Equity Ex-Top 100 Long-Short Fund | 17 |
| Allocator | Hybrid Investment Strategies – Active Asset Allocator Long-Short Fund | 10 |
| Sector Rotation | Equity Oriented – Sector Rotation Long-Short Fund | 4 |

Each strategy has Regular/Direct × Growth/IDCW variants, kept as **separate series** (not merged).

## The fetcher — `fetch_amfi_sif.py`

```
--from YYYY-MM-DD     start date (default 2025-10-01)
--to   YYYY-MM-DD     end date   (default today)
--filter REGEX        name/category filter (default: long[- ]?short|allocator|sector rotation)
--out FILE            output (default nav_data.json)
--url TEMPLATE        history URL override, placeholders {sd} {frm} {to}
--chunk-days N        split long ranges into <= N-day windows (default 365), deduped by (code,date)
--workers N           parallel fetch workers (default 8)
--latest              today's snapshot only (uses api/sif-latest-nav)
--serve               serve this folder on 127.0.0.1:8765 with CORS + a /refresh route
--host / --port / --dir   serve options
```

- **Any date range works** and is chunked automatically; transient failures retry with backoff;
  rows are deduped by `(scheme code, date)`.
- **`nav_data.json`** shape:

  ```json
  {"generated":"2026-08-01T02:41:03+00:00",
   "source":"AMFI api/sif-nav-history (historical_period) + api/sif-latest-nav",
   "schemes":[{"code":"SIF-79","name":"Apex Hybrid Long-Short Fund-Direct Growth",
               "cat":"Hybrid Investment Strategies - Hybrid Long-Short Fund",
               "sif":"Apex SIF","isin":"INF209K30016",
               "series":[["2026-03-30",10.02],["2026-03-31",10.0431], ...]}]}
  ```

### How to refresh the data

- **From the CLI:** re-run `python fetch_amfi_sif.py --from … --to …` to overwrite `nav_data.json`.
- **From the page:** click **Fetch AMFI ↻** (needs `--serve` running). It calls
  `GET /refresh?from=&to=`, which re-downloads live from AMFI, rewrites `nav_data.json`, and
  returns the fresh JSON — the table recomputes in place.
- **Drag-and-drop:** drop a raw AMFI file (`NAVAll.txt` or a NAV **history report**) or a
  `nav_data.json` onto the page. The two AMFI layouts order their columns differently, so
  columns are mapped **by header name** (`Scheme Name` / `Net Asset Value` / `Date`), never by
  fixed index.

## Portfolio disclosures — `fetch_sif_portfolios.py`

Every disclosed holding shown in the dashboard traces back to a file the fund house itself
published. **This is separate from NAVs and works differently**, because of how the data is
published:

- SIFs disclose portfolios **bi-monthly** (every alternate month — a SEBI rule), not monthly.
- **AMFI does not host the holdings.** Its "Portfolio Disclosure" page, like the mutual-fund
  one, only *links out* to each AMC's own website. Every `api/sif-*` portfolio endpoint 404s —
  there is no holdings JSON API. So portfolios must be pulled **per-AMC**, from heterogeneous
  Excel/PDF files on ~17 different AMC sites.

The pipeline is therefore **registry-driven**, with one *adapter* per AMC file layout:

```bash
pip install -r requirements.txt                    # openpyxl + pdfplumber (portfolio pipeline only)
python fetch_sif_portfolios.py                      # all AMCs in the registry, latest disclosed period
python fetch_sif_portfolios.py --amc apex --period 2026-05
python fetch_sif_portfolios.py --file mine.xlsx --amc apex   # normalise a hand-downloaded file
python fetch_sif_portfolios.py --list              # show what's already stored
```

**What it does per AMC:** reads [`portfolios/registry.json`](portfolios/registry.json) → **discovers**
the disclosure file for the period → downloads it verbatim into `portfolios/raw/<amc>/<period>/` →
**parses** it into normalised holdings under `portfolios/data/<period>/<amc>__<fund>.json` → rebuilds
`portfolios/index.json`, mapping each dashboard **scheme code** (a portfolio is per *fund*, so it fans
out to that fund's Direct/Regular × Growth/IDCW variants) to the periods available. Everything is
**committed to the repo** — raw files and normalised JSON are versioned, so you get a history you can diff.

- **Discovery** (`discovery.method` in the registry): `http_listing` (regex a page for the file URL),
  `template` (build candidate month-end URLs from a date template, keep the ones that 200), or `manual`
  (pinned URLs, for sites behind a WAF / SPA / API-only).
- **Parsing** (`adapter: sebi_xlsx`): the SEBI-standard monthly-portfolio layout that *every* AMC uses,
  so one parser covers all of them; it also unpacks a zip-of-xlsx bundle (ICICI) and reads the statement
  date from inside the sheet. Funds map to dashboard schemes by **strategy** (hybrid / equity long-short /
  ex-top-100 / allocator / sector), which survives the wildly inconsistent fund-name lines.

A normalised `data/*.json` holds `{fund_name, as_of, period, source_url, raw, net_assets_cr, managers,
strategy, presentation, allocation{equity,debt,money_market,cash_other}, sectors[], derivatives[]
(long/short F&O legs), top[], holdings[]}`.

### Coverage

Fetches real disclosures for **~17 funds across 12 fund houses** — Apex (Aditya Birla SL), Titanium
(Tata), DynaSIF (360 ONE), Arudha (Bandhan), iSIF (ICICI Prudential, a 4-fund zip), Diviniti (ITI),
Magnum (SBI), Arthaya (Union), Sapphire (Franklin Templeton), Platinum (Mirae), RedHex (HSBC), WSIF
(The Wealth Company). Four SIFs (qsif/Quant, Summit/Invesco, Infinity/Kotak, Prism/Jio BlackRock) are
too new to have disclosed a portfolio yet — they're registered and picked up automatically once they
publish. See [`handover.md`](handover.md) for the full status table and per-AMC notes.

### Adding another AMC

1. Add an entry under `amcs` in `registry.json`: `site`, `nav_sif` (matching the `sif` field in
   `nav_data.json`), a `discovery` block (`http_listing` + `file_pattern`, `template` + `url_template`,
   or `manual` + `files[]`), and `managers`/`strategy`/`presentation` (per-fund overrides via a `funds`
   map when an AMC runs several funds with different managers).
2. If the layout is the usual SEBI monthly portfolio, `adapter: sebi_xlsx` already handles it. The
   `--file` path also normalises any hand-downloaded sheet without writing code.

In the dashboard, each row shows the **brand + parent AMC** and a `▣` badge when a portfolio exists.
Click a scheme to expand it: the **Portfolio (disclosed holdings)** panel shows the period selector,
**strategy + fund managers + presentation link**, top holdings, asset allocation, long/short F&O
exposure, and equity sectors — with links to the raw file and the AMC's disclosure page. Schemes with no
disclosure yet still show the strategy/manager and a note (SIFs report bi-monthly), so the page is
always complete.

## The metrics

Recomputed on every From/To (or any control) change, using **only the NAVs inside the window**.
Let `r(t) = NAV(t)/NAV(t−1) − 1`, `D` = trading days/year (default 252), `Rf` = risk-free %
(default 6.5). `n` = number of daily returns = `Obs − 1`.

| Metric | Definition |
|---|---|
| **Avg daily %** | `mean(r) × 100` |
| **Ann Ret %** | `mean(r) × D × 100` — simple annualisation, **not** CAGR |
| **Ann Std %** | `stdev_sample(r) × √D × 100` (sample = `n−1` denominator) |
| **Sharpe** | `(AnnRet − Rf) / AnnStd` |
| **Sortino** | `(AnnRet − Rf) / (√(Σ min(r,0)² / n) × √D × 100)` |
| **Max DD %** | largest peak-to-trough NAV fall in the window |
| **Max RU %** | largest trough-to-peak NAV rise |
| **Recovery** | days from the max-DD trough until NAV regains the prior peak; **"not rec."** if not regained by the To date. Toggle: trading days vs calendar days |
| **1D %** | trailing 1-trading-day return, as of the window's To date |
| **1W %** | return vs the last NAV on/before (To − 7 calendar days) |
| **MTD %** | month-to-date: return vs the last NAV of the prior month |
| **1M %** | return vs the last NAV on/before (To − 1 calendar month; month-end clamped, so 31 Jul − 1m = 30 Jun) |
| **2M / 3M / 6M %** | return vs the last NAV on/before (To − 2 / 3 / 6 calendar months) |
| **YTD %** | calendar year-to-date: return vs the last NAV on/before 31 Dec of the prior year |
| **FYTD %** | Indian financial year-to-date (FY starts 1 Apr): return vs the last NAV on/before 31 Mar of the FY start |
| **Total %** | `NAV_last / NAV_first − 1` |
| **Win %** | share of days with `r > 0` |
| **G/P** (gain-to-pain) | `Σ r⁺ / |Σ r⁻|` |
| **Calmar** | `AnnRet / MaxDD` |
| **Obs** | NAV observations in the window (returns = Obs − 1) |
| **CAGR** | `(NAV_last/NAV_first)^(1/years) − 1` — shown in the expanded row for contrast |
| **Range** | first → last NAV date actually present in the window |

**Why Range and Min obs matter.** Several SIFs launched only weeks ago, so a common calendar
window still yields very different observation counts, and a Sharpe on 30 observations is noise.
Rows below **Min obs** (default 10) are greyed out and flagged ▲. A row that annualises to a
huge number (e.g. a fund up 8% in its first 6 trading days → ~125% "annualised") is a
short-window artifact, not alpha — the fetcher and the header status line surface these.

### Colour bands & tooltips

Conditional tints on Sharpe, Sortino, Calmar, Gain-to-pain, Win %, and Max DD:
green = strong/good, amber = weak, red = poor (Max DD reddens with magnitude); the tints are
theme-aware so they stay legible in dark mode. Every column header carries an **ⓘ hover tooltip**
that defines the metric in plain English (e.g. what Sharpe/Sortino actually mean for an investor).

### UI

Sticky control bar (From, To, Risk-free %, Trading days, Min obs, Recovery mode, Recompute,
Max range, Fetch, Export CSV, "my funds" regex — default `apex`, search), plus three filter
dropdowns:

- **Strategy** — show only Hybrid Long-Short, Equity Long-Short, Ex-Top 100 SMID, Sector
  Rotation, Allocator, Other, or All.
- **Plan** — All / Direct only / Regular only.
- **Option** — All / Growth only / IDCW (Dividend).

The three compose, so e.g. *Ex-Top 100 SMID + Direct + Growth* isolates one comparable series
per AMC. The 1D/1W/MTD/1M/2M/3M/6M/YTD/FYTD trailing-return columns update with them and are anchored
at the window's To date. Each row shows the fund **brand + parent AMC** and a `▣` badge when a
portfolio disclosure exists. Table grouped by strategy, sortable on every column, sticky header,
tabular-lining numerals. Click a scheme name to expand its NAV path, underwater (drawdown) curve, and
the disclosed-holdings panel; each row also carries an inline underwater sparkline. **Mobile:** the
scheme-name column stays pinned while the metrics scroll sideways, with compact spacing and a
flow-with-content footer. Visible keyboard focus, `prefers-reduced-motion` respected.

## Data notes from the live pull (2025-10-01 → 2026-08-01)

- **111 scheme variants, 9,757 NAV points**, earliest NAV **2025-10-08**, latest **2026-07-31**.
- **No duplicate dates. No daily NAV jump > 10%** anywhere (max single-day move ≈ 2.7%) — so the
  handful of very high annualised returns are short-window simple-annualisation, **not** unit
  splits or NAV gaps.
- **20 of 111 variants have < 30 observations** (recent launches — Summit has only 6 days,
  several DynaSIF/Jio BlackRock variants < 25). Treat their ratios with caution; the dashboard
  greys them below the Min obs threshold.
- The downloaded universe includes AMCs beyond the original hint list (e.g. Summit, Infinity,
  DynaSIF, Arthaya) — the fetcher takes whatever AMFI actually publishes.
